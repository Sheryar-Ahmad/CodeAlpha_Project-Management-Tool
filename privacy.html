YOUR DATA

Privacy & your workspace

Orbit is a project management application by Sheheryar Ahmad. This notice describes the current personal and shared-project implementation.

Local demo

Demo tasks, project details, notebook entries, and work logs are saved in this browser’s local storage. They are not uploaded to the account database. Anyone using the same browser profile may see them. Use Reset demo to replace them with samples, or clear the site’s browser storage to remove them completely.

Accounts and tasks

Account mode stores your name, email address, a salted password hash, and your tasks in MongoDB. Plaintext passwords are not stored. Task data includes titles, project labels, descriptions, priorities, statuses, blocker reasons, due dates, checklist steps and their completion states, notes, resource link labels/URLs, archive/trash state, repeat schedule and occurrence links, stable project references, and timestamps. Private project records also store a name, description, start/target dates, and planning status and milestones. Notebook records include entry types, titles, content, dates, and timestamps. Manual work logs include activity, project label, work date, minutes, notes, and timestamps.

Shared projects

Inviting an existing Orbit account stores a project membership and invitation status. After acceptance, that person can see and work on connected project tasks, team notes, task discussions, and review history. Private notebook entries and personal work logs are not shared. The project directory shows names; invitations are in-app only.

Assignments store the chosen account reference. Comments store an author, body, and timestamps. Review requests store requester/reviewer references, a captured task title and description, messages, decisions, and timestamps. Review history remains with the project after task removal. Removing membership ends access on subsequent requests and preserves existing work; an already-authorized request may finish concurrently.

Accepted guests see only the project brief, milestones, and active-task titles, descriptions, priorities, statuses, and dates through a read-only portal. Task notes, resources, conversations, review history, and other team data are excluded. Guest access requires an account and can be removed by the owner.

Requests and dependencies

Work requests store proposed task details, requester references, triage responses, status, and the resulting task reference. Accepted project members can see them. Intake history remains with the project after task removal. Dependency records store pairs of task references and a revision counter; tasks moved out of the project no longer reveal their titles through those links.

Focus timer

Timer settings, remaining time, and a running session’s deadline are saved in this browser’s local storage. Demo and account timers use separate keys. They are not synced to MongoDB or other devices. Your written focus goal is not stored. Anyone with access to this browser profile may inspect its local storage; clear site storage to remove timer records.

Sessions and request limits

A required HTTP-only cookie keeps you signed in for up to seven days. The database stores a digest of the session token, its account reference, and its expiry. Signing out revokes the current session. Request limits use hashed client-address counters with expiry dates to reduce abuse.

Task exports

Export tasks downloads your task content, including archived and trashed records, as a JSON file. The file excludes passwords and session tokens, but your written content may be sensitive. Keep it private. Exporting does not remove the stored records. This task-only export does not include project metadata, notebook entries, work logs, discussions, assignments, or review records.

Imports and account recovery

Task imports validate an Orbit backup and restore into a new owned project. Completed import jobs discard their copied task content and retain retry metadata. This browser temporarily retains only the import key and project name for retries; select the original backup again after a reload. Recovery codes are generated after password confirmation, shown once, and stored only as a digest. A code can reset your password once and revoke older sessions. Keep the code private. Changing a password also revokes previous recovery codes.

Deleting data

Archiving keeps a task saved outside active work. Delete moves a task to Trash, where you can restore it to the board or permanently delete it. Trash is not automatically emptied. Notebook entries and work logs can be permanently deleted directly after confirmation. Account settings offers password-confirmed account deletion. It freezes access and removes owned projects (including shared projects), tasks, personal records and authored contributions. Other accounts keep their owned work. Interrupted deletion can be resumed; configured daily maintenance retries cleanup. Minimal account-ID cleanup markers remain for up to 90 days to purge in-flight writes. Hosting/database backups may retain copies according to provider policies. Saved one-time recovery codes can reset a password; there is no email recovery fallback. Clearing browser data does not delete account records from MongoDB. Do not use this prototype for confidential or regulated information.

Hosting and external services

A deployed instance uses its hosting provider and MongoDB deployment to serve and store data. Providers may process network metadata such as IP addresses. Orbit includes no advertising or analytics scripts and does not intentionally publish private task content.

Development status

Production backup retention rules and a support contact must be finalized before a broad public release. The public source repository contains application code, not your account records or database credentials.
