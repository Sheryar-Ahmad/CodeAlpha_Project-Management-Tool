# A short Orbit walkthrough

Aim for about 90 seconds. Use the local demo and illustrative tasks, not private account data.

1. **The problem (10 seconds):** “Small projects get harder when deadlines, decisions, and next steps are scattered. Orbit brings them into one personal workspace.”
2. **See what matters (15 seconds):** Open Action Center and explain the reasons beside urgent work. Switch to the monthly calendar and create a task for a selected day.
3. **Make work actionable (15 seconds):** Add checklist steps, save, and complete one. Mention that recurring tasks preserve the completed occurrence.
4. **See the project (15 seconds):** Open Projects, show its brief, milestone progress and explained health flags. Switch to the timeline to compare recorded dates.
5. **Keep context (15 seconds):** Open the project notebook, show a decision and meeting record, then create an editable meeting follow-up.
6. **Record effort (10 seconds):** Open Work log, record minutes, and show weekly totals. Explain that saved logs are separate from the local focus timer.
7. **The implementation (10 seconds):** “React powers the workspace, Express validates requests, and MongoDB saves private account records. The demo stays in local browser storage.”

Close with the repository link and, after deployment, the verified live URL. Orbit supports personal and explicitly shared project workspaces. The live site is https://orbit-by-sheheryar.vercel.app. Dates and manual time records are not delivery forecasts or proof of billable hours. Do not claim production performance, security certification, search rankings, or ad revenue without evidence.

## Team workflow

Use two browser profiles: invite an existing account from Team projects, accept on the other account, add a shared task, assign it, and open Discussion. Record a shared decision in Team notes, then request a review and approve it from the other account. Remove access and refresh to demonstrate the permission boundary. Explain that private notes stay separate and invitations are in-app only.

Show the project tool tabs: link two tasks in Dependencies, reject a circular link, then submit a Work request as a member. Accept it as the owner and point out the new task. Retry acceptance to demonstrate duplicate prevention. Work requests support authenticated intake and optional owner-enabled public request links; explain that public submitter names are unverified.

## New-user tour and recovery

Offer the optional welcome guide, jump to Calendar, minimize it to use the workspace, then reopen it from the book button. Open Account settings and explain that a recovery code must be generated while signed in and saved privately. Never show a real recovery code or password in a recording.
